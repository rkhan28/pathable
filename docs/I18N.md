# Internationalization

## Model

- **next-intl 4** with `next/root-params`. URL prefixes `/en`, `/fr` map to BCP 47 tags `en-CA`, `fr-CA` (`src/i18n/locales.ts`).
- Twelve languages are registered: English (Canada), French (Canada), Spanish, Arabic, Simplified Chinese, Traditional Chinese, Hindi, Urdu, Bengali, Punjabi, Tamil and Portuguese. **Only languages whose `status` is `complete` are enabled** — a unit test enforces that the enabled list and the registry agree.
- Planned languages appear in the language menu as disabled items marked "Coming later", so people can see they're on the way without landing on half-translated pages.
- All user-facing text — including screen-reader announcements, map control labels, directions, errors and recommendation reasons — comes from the catalogues. The API returns codes, never prose.
- Messages use ICU syntax (plurals, select). `src/global.d.ts` types `t()` keys against the English catalogue, so a missing key fails `tsc`.
- Formatting (distances, durations, percentages, relative times) uses `Intl` with the active locale (`src/lib/format.ts`).
- Switching language keeps the current page, query string, trip and selected route.

## Quality gates (`src/messages/messages.test.ts`)

- French has exactly the same keys as English.
- Placeholders match key-for-key (`{count}`, `{distance}`…).
- Every message parses as valid ICU in its locale and is non-empty.
- Fewer than 6% of French strings may be identical to English (brand names, units, pure placeholders).
- RTL languages are registered as RTL.
- "100% safe" never appears except in a negation.

## RTL readiness

- Layout uses logical properties (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`, `border-s`), and directional icons use `rtl:rotate-180`.
- The root `<html dir>` is set from the locale registry.
- An e2e test renders key pages with `dir="rtl"` and checks for horizontal overflow.
- Line-height increases automatically for Arabic, Urdu and Indic scripts.

## Adding a language

1. Copy `src/messages/en-CA.json` to `src/messages/<code>.json` and translate every string. Use a fluent reviewer — preferably someone who uses mobility aids — for accessibility terminology (e.g. "curb ramp" is "bateau de trottoir" in Canadian French).
2. Run `npm test`; fix parity and ICU errors.
3. In `src/i18n/locales.ts`, set the language's `status` to `"complete"` and add its code to `ENABLED_LOCALES`.
4. If the script needs a better system font fallback, add it to `--font-sans` in `globals.css`.
5. Run the e2e suite including a scan of `/<prefix>` pages, and a manual screen-reader pass in that language.
